Architecture

How a download travels

Browsers can't run programs directly, so the extension talks to a small Python host through Chrome's native messaging API.

  1. Extension popup

    Reads the active tab, checks it is a YouTube video or playlist, and lets you choose one video or all of them.

    popup.js

  2. Native messaging

    The service worker opens a port to the host. Messages are JSON, length-prefixed over stdin and stdout.

    service_worker.js

  3. Python host

    Opera GX starts the packaged host on demand. It validates the URL and runs yt-dlp with progress hooks.

    native_host.py

  4. FFmpeg merge

    The best video and audio streams are merged into one MP4 and saved to the Downloads folder.

    .mp4

Details

Engineering notes

Best quality first

Formats are ranked by resolution, frame rate, HDR and bitrate. MP4 video with M4A audio is preferred so the merged file plays everywhere.

Playlists don't stop on one bad video

A private or deleted entry is skipped and the rest keep downloading. The popup shows which item of the playlist is in progress.

Progress without flooding the popup

yt-dlp reports progress constantly, so the host sends at most four updates a second (0.25 s interval).

No setup at download time

The host is packaged with PyInstaller and registered with the browser by an installer, so nothing has to be opened manually.

Clear failures

Missing FFmpeg, a non-YouTube page or a URL without a playlist ID each produce a specific message in the popup.

Debuggable

Stray output is redirected away from the messaging channel and everything is written to a log file, so the protocol never breaks.
